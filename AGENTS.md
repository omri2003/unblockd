# unblockd: notes for agents working on this repo

Read first: what exists, why it's built this way, traps that already bit. Keep it current: **docs move with the code**, in same commit.

## What it is

Dependency-aware ticket board for humans and AI agents. One ticket = one JSON file in project repo (`<project>/tickets/`), committed with code it describes. Front doors over one core: web board (`unblockd.web`), MCP server (`unblockd.mcp_server`), CLI (`unblockd.cli`), chat asking Claude about boards (`unblockd.chat`).

A dead connection frees its lock (no stealing). Writes without lock are short transactions taking same row, so `version` and event number `n` only grow in commit order. Connections per thread (`connect`/`disconnect`). Every write takes lock (`_tx = lock`), so version / event numbers grow in commit order. ## Data model

Ticket fields (`FIELDS` in store.py; add one there → API + MCP accept it):
- `title`, `owner`, `pillar`, `pillar_step`, `section`, `waiting_on`, `body`, `touches` (paths/globs work edits), `docs` (repo paths/folders/globs to read), `id`, `created`, `updated`.
- `status`: todo|doing|review|done writable. `pending` is derived only: writing it refused; stored `pending` (old file) reads as todo.
- `priority` P0-P3|null. `tags` lowercase; `agent:<name>` routes. `blocked_by` (ids). `parent` (group/epic id; NOT blocker).
- `done_at` (read-only, UTC ISO): set by create / update / `complete()` when status becomes done, cleared when it leaves done; old tickets lack it → UI uses `updated`.
- `asked_at` / `asked_by` (read-only): `ask()` sets both (now / agent), `answer()` clears them. `waiting_on` set or changed by update gets `asked_at` = now if empty, never `asked_by` (= hand-parked). Clearing `waiting_on` clears both. Writing either refused like `result`.
- `done_when`: list of short acceptance criteria (bar for done; background goes in `body`). Top of `context()`; copied as `done_when` onto the `complete` note; drawer = checklist, edit form = one per line; not copied by split.
- `proposed_by` (read-only): agent that created it on board with `agent_tickets: "propose"`; set by `create(agent=)`, cleared by `accept()`; writing refused like `asked_by`; while set → pending.
- `skills` / `mcp`: names from board's registries, validated in `Store._check_caps` like `components` (unknown → TicketError listing registry; names already on ticket tolerated; deduped). Copied by split. NOT in schema `required`.
- `components`: keys of board's architecture notes ticket changes (explicit link to Map). Validated in `Store._check_components` against `knowledge.components` (lazy import: knowledge imports store): unknown → TicketError listing keys; architecture off/empty → refused with setup steps; keys already on ticket tolerated (removed note never locks it). Deduped, order kept, copied by split.
- `milestone`: key of board's `milestones` (roadmap version; separate from `parent`). Validated in `Store._check_milestone` (unknown → TicketError listing keys; no milestones → refused with setup step; key already on ticket tolerated, so removed milestone never locks it). Copied by split. List filter `milestone=`, `-` = none.
- `result`: null until `complete()`: {summary, files, refs, handoff, by, at}; see Claims. **Done without a result** (CORE-68, tests/test_report.py): `update` / `create` to done with no `result.summary` returns `warnings` (`store._NO_REPORT`, names complete(); never refused: solo flow works); MCP `_ack`, REST, CLI and `Remote` pass it through. `update(by=)` (REST PATCH body `by`, CLI `update --by`, `Remote.update(by=)`, github.py sends `github`) only names who: the `done` event's agent = `agent` or `by` or `human`. `report(id, by, summary, files, refs)` (MCP `report_ticket`, CLI `report ID SUMMARY [--by] [--file] [--ref]`, REST `POST tickets/<id>/report {by?, summary, files?, refs?}`, `Remote.report`): a person writes the missing summary: sets `result` (by = that person, handoff empty), a `complete` note (status done), logs `reported`; refused unless done with no summary, for a worker (`_human_only`), empty by / summary.
- `rev` (read-only int): bumped by `Store._write` = every ticket-file write (create = 1, old files read as 0); writing refused like `result`. `claims.json` is separate, so heartbeats and `_keepalive` do NOT bump it. `update(..., expected_rev=)` raises `Conflict` (a `TicketError`, REST 409) if it differs under lock. REST `PATCH` reads `If-Match: <rev>`; no header = last write wins; CLI/MCP send none. UI edit form sends rev it opened with (`data-rev`); on 409 reloads, keeps draft.

Derived on every read (`_decorate`):
- `effective_status`: todo + open blocker / `waiting_on` / `proposed_by` = pending; else todo + active linked branch = doing (see Branch evidence).
- `branches` (not-done tickets): linked unmerged branches `[{name, sha, at, author, commits, via: [name|commit|file], active, edit?: {status, notes}}]`.
- `open_blockers`, `blocks`, `missing_blockers`, `children` + `progress` {done, total} (direct children only), `unblocks` (open tickets downstream, transitive).
- `unreported: true` (only when true): done, no `result.summary`, `done_at` on or after `store.UNREPORTED_SINCE` (2026-11-21, the day CORE-68 shipped, so ~100 older hand-closed tickets never flood); UI-79 shows it: digest count, Done card mark `no summary` (in place of its age, so title keeps room), List row's why column "Finished without a summary" (`lwhy`; CORE-83). `create` and `create_many` (per `#N`) of a done ticket warn like a hand move.
- `stale_days` (doing only); `score` = PRIO_WEIGHT (P0 8, P1 4, P2 2, P3 1) x (1 + unblocks).
- `agent` (routed profile); `claim` (live: agent, profile, claimed_at, heartbeat_at, note, principal?, branch?, until?, seen, `expires_at` = `_expires` (profile lease or heartbeat `until`): UI lease bar's length, stripped with heartbeat_at by UI's `hbStrip`); `files` (names in tickets/files/<ID>/).

Store rules:
- IDs `PREFIX-N` (create with prefix → next free number, also skipping numbers in `legacy_files` and, from branches.json `id_max` (`Store._taken_elsewhere`), numbers origin's default branch or an unmerged branch already holds: two clones used to both make NUT-88, CORE-76; no scan = no effect).
- `delete` (under lock): drops claim, removes `tickets/files/<ID>/`, logs `deleted`, returns ticket + `referenced_by` (tickets whose `blocked_by`/`parent` still name it; not edited, they show it as missing blocker).
- `blocked_by`: loops refused, loop spelled out. Ids ADDED by create/update must exist ("no ticket X on this board"); ids already on it that went missing are tolerated (split children inherit them too).
- `parent` must exist, no loops (create/update). Filter `list(parent=X)`, CLI `list --parent`, MCP `list_tickets(parent=)`; no REST filter (UI filters client-side). Deleting parent leaves children pointing at it, with no `children` on anyone.
- A profile-named worker cannot set `doing`/`done`/`review` via `update` (see Worker guardrails under Traps).
- `doing` with open blockers refused (in `update`, so web/MCP/CLI all get it; `claim` only takes ready tickets).
- Owners and pillars must be configured ones; unknown `agent:<x>` tags refused.

## Config: `<tickets>/unblockd.json`

Optional; `DEFAULT_CONFIG` in store.py is schema; unknown keys refused.
- `id`, `title`, `owners` [{name, kind: human|agent}] (`kind` must be human|agent), `default_owner`, `pillar_label`, `pillars` [{key, name, color, color_dark}], `stale_days`, `lease_minutes`, `lease_max_minutes` (cap for `heartbeat(until=)`, default 240), `legacy_files`.
- `wip_limit`: int|null (UI In-progress WIP badge; none when null). `done_window_days`: int > 0, default 7: Done column shows only tickets done that recently (UI only; edited in this file, no settings form).
- `agents` [{name, tags, pillars, model, instructions, docs, lease_minutes}], other keys refused; `lease_minutes` (0 < n <= 1440) overrides board's for that profile's claims (`Store.lease_minutes(profile)`, AI-58); `agents[].skills` / `mcp` = registry names (unknown refused). `worker_tools` / `agents[].tools` / `agents[].tools_off`: MCP tool names, `TOOL_RE`; edited from Agents panel.
- `docs`: knowledge for every ticket. `docs_by_tag` {tag: [paths]}: only tickets with that tag get it; keys `TAG_RE`, values non-empty path lists without `..`.
- `skills` {name: {path, description?}}, `mcp` {name: {hint, doc?, required?}}: registries of what agent harness provides; unblockd declares, never starts server or stores secret. Checked in `store._check_caps` at load: names `NAME_RE`; skill `path` / mcp `doc` = existing text file inside project (`knowledge._inside`), NOT under tickets folder; description one line <= 200; hint required, one line <= 300; unknown keys refused (so no command/url/env).
- `use_skills` / `use_mcp`: registry names every ticket gets (simplest board level that still lets ticket add non-board-wide one; "every registry entry" would leave nothing to add).
- `context_budget`: chars inlined per context, default 60000. `architecture`: repo folder of component notes, default `docs/arch`; on when folder exists, `null` = off. `review`: bool, default false (review gate, see Claims).
- `schema`: null = off, else `{prefixes: {PREFIX: meaning <= 80 chars}, required: [done_when|priority|touches|docs|pillar|owner|parent|body], tags: [...], body_template}`; sub-keys optional, unknown refused (see Schema and proposal gate). `agent_tickets`: `open` default | `propose` (opt-in proposal gate).
- `session_tickets` (int > 0 or null, default 5), `docs_resend` ({claims, minutes} ints >= 0): see Worker guards.
- `milestones`: roadmap `[{key, title, goal?, exit_criteria?, target?, closed?}]` in order; `_check_milestones`: key `MILESTONE_RE`, unique, title <= 80, goal one line <= 300, exit_criteria <= 20 lines, target ISO date, closed bool, unknown keys refused.

## How the pieces work

## Why files, not a database

Files stay DEFAULT connector (owner decision 2026-11-01, epic CORE-27: organisations also get SQL / MongoDB connectors, chosen per board, with migration between them; store.py rules are same for all, see `files.py`). For board in repo: **one JSON file per ticket in the project's git repo is the product.** Tickets are reviewed in PRs next to code they describe, work offline, diff and merge like source; agents need no server to read or write them (CLI/MCP open folder). A database would give up exactly that. Measured at 5,000 tickets (Windows, 2026-10-20, synthetic board): before cache `list()` 0.41 s, `get()` 0.40 s, claim + release 1.6 s (0.7 s holding lock, 15,000 file reads); with it `list()` 33 ms, `get()` 14 ms, claim + release 0.24 s, `/api/needs` 63 ms.

**The cache** (files.py `_RAW` / `_LOG`, store.py `_DEC` keyed by connector's `key`; module-level so every Store on folder shares them: web server builds one Store per request). `FileBackend._scan()` = one `os.scandir` per call; file is re-parsed only when its `(inode, mtime_ns, size)` stamp changed (`os.replace` makes new inode, so rewrite within one clock tick is still seen; DirEntry on Windows has no inode, but its mtime is 100 ns). `_board()` = decorated board by id, re-derived only when `backend.version()` (stamps, `claims.json`'s stamp, attachment names), date or config changed. `files._events()` = activity log parsed incrementally (only bytes appended since; another inode or shorter file = reread; half-written line waits). Files stay only truth: nothing written back; git pull, hand edit or another process's write is seen on next call (in web server: in-place editor save within `files.SCAN_REUSE_S`). **Stat reuse** (CORE-60, test_cache `ScanReuseTest`): `FileBackend._scan()` outside lock returns folder's last pass while it is younger than `files.SCAN_REUSE_S` and `_WROTE[folder]` (bumped by `write`, `delete` and at end of every `lock()`) has not moved since AND folder's own `mtime_ns` (one `os.stat`) is unchanged; inside `lock()` it always stats. Default 0 (CLI, MCP, tests: exact); `web.main` sets 1 s, so one page load (tickets, needs, architecture, boards) pays one stat pass. Folder mtime: `os.replace` (every store write, any process; git checkout) changes it, so another process's write is seen on next read (PR #73 CI smoke: CLI wrote, page refreshed at once, server served old pass); in-place editor save does not, so that alone waits out window (why mtime is not the only check). Database connectors need none: unchanged board `version` already skips row scan with one query; reusing past that would hide another connection's write. `list()` / `get()` / `_all_raw()` return copies (`_copy`, two levels deep): never hand out cached dict. `unblocks` = one bitset pass over reverse `blocked_by` graph, not DFS per ticket.

The real limits, and what already answers each:

| Limit | Answer |
|---|---|
| The file lock only works on one filesystem, so every agent had to run where the tickets are | Remote CLI: `UNBLOCKD_URL` sends commands to the one web server, whose Store does the locking |
| Every open browser re-downloaded the whole board every 4 s | `ETag` + 304 on GET; the UI sends `If-None-Match` |
| `activity.jsonl` grew forever and was parsed whole | Rotated at 5 MB, read newest-first and stopped early |
| Parallel `create`/`update` raced (lost tickets, lost claims) | `create`/`update`/`delete`/`split` run under the same lock as claims |

Revisit SQLite only for the **runtime** state (claims, activity), never for tickets, and only if remote mode stops being enough.

## Traps that already bit

- `.board` is board's grid class: any other element with class `board` turns into 4-column grid. (Board links in chat use `.bref`.)
- `[hidden]{display:none!important}` is required: component classes set `display` and would override attribute. `[hidden]` on `#depSeg` works only because of it (`.vico-g` sets `display:inline-flex`).
- `_locked` steals lock older than 30 s through `_steal`, which holds `lock.steal` and re-checks age first. A bare `lock.unlink()` after reading stale mtime lets two processes both "steal": second deletes fresh lock first just created and both run critical section. After `_steal` loop falls through to deadline check and sleep (stuck `lock.steal` guard must not busy-spin or outlive 10 s deadline). `claims.json` that is not valid JSON raises `TicketError` telling user to delete that file (runtime state; live workers re-claim); it used to read as `{}`, silently dropping every live claim.
- **Windows lock re-create**: right after holder deletes `lock`, Windows keeps it "delete pending" and `os.open(O_CREAT|O_EXCL)` raises `PermissionError`, not `FileExistsError`; `_locked` once let that escape, so under contention concurrent `add_note` was lost (flaky test_claims concurrent-note test, ~1 full run in 4). It now waits and retries like for held lock (real permission problem still fails after 10 s deadline, with clear message).
- `_locked` must stay re-entrant: `claim()` holds lock and calls `next_ready()`, which may sweep expired claims under same lock.
- Expired claims are swept at START of `list()`/`get()`; sweeping inside `_decorate` was too late (tickets were already read as doing).
- **Indicator measured before its frame** (UI-37): `slidePill` must add `.sl` (makes control `position:relative`) BEFORE it creates and measures new `.ind`; measured first, `offsetLeft/Top` were relative to drawer (e.g. 20, 124 px) and ticket's status pill slid in from below on its first open.
- **Holder rule** (`Store._holder_only`): ticket with live claim + caller naming itself as agent that is not holder → `update` (any field), `split` (`by`) and `delete` (`agent`) refused; no agent identity (web without `agent`, human CLI) is unchanged. MCP `split_ticket`/`delete_ticket` require `agent`; CLI `--agent` on update/delete (`split --by`); REST `DELETE tickets/<id>?agent=`, `Remote.delete`.
  **Worker guardrails** (accident prevention, NOT security: agent with shell can edit JSON files; per-user tokens are later fix). "Worker-shaped" = name resolves to configured profile (`profile_of`: `backend`, `backend-1`). Such actor cannot `answer` / `reject` / `accept` / `approve` (`_human_only`: "tell the human (ask_human) or add_note"), cannot `update` status to doing / done / review ("use claim_ticket / complete / ask_human"; todo is allowed; closes review-gate bypass and ghost `doing`) and cannot `delete` human-owned ticket. EVERY actor: no self-approval (`answer` by == `asked_by`, `accept` by == `proposed_by`, `approve` and `reject` by == `result.by`). Boards without profiles, and names matching no profile (`claude`, `omri`, `human`, owner's own Claude on solo board), are unrestricted, so solo flow is unchanged. Tests: tests/test_guardrails.py.
- Anything `chips()`/`slidePill` reaches runs during init (`applyConfig` -> `renderBar`), so every `const` it reads must be declared above first call: `reduce` used to sit at line ~1215 and page died with "Cannot access 'reduce' before initialization". A `startViewTransition` callback is async: tests (and code) clicking view button must wait for state (`waitForFunction`), not assert right after click.
- **Git worktrees** (`Store.rt`, `store.linked_worktree`): each worktree has its own copy of committed `tickets/`, so CLI run there used to get its own lock and its own (gitignored, empty) `claims.json` and could claim ticket another worktree's worker held; where `tickets/` is NOT committed (this repo: board is separate repo) worktree had none and `Store()` silently created empty board. Now tickets folder inside linked worktree (its `.git` is file whose gitdir has a `commondir`; submodules have none) keeps runtime state in main checkout's same folder, and CLI refuses missing `--dir`. Every runtime path goes through `store.rt` (github.py `load(rt)`, notify.py), never `tdir / ".unblockd"`.
- `pending` is derived, never settable: bulk bar, move menu and drawer omit it; chat prompt lists it only as filter value.
- `pkill -f <pattern>` in shell whose own command line contains pattern kills shell (exit 144). Use `pgrep -f "[u]nblockd.web" | xargs -r kill` in command that doesn't start server too.
- urllib capitalises header names (`X-api-key`); compare headers case-insensitively in tests.
- A regex like `/^BUG-10$/` never matches `id + ' ' + title` (the `$` meets title), hence extra test on bare id in `matches()`.
- Closing drawer rewrites URL: keep `location.search` (`?board=`) when clearing hash.
- `compose.yaml` must pass `.env` values into container explicitly (`environment:`); `.env` alone only feeds `${...}` interpolation.
- An ETag (or any "last seen" token) must be stored WITH data it describes. `loadNeeds` once set `nEtag` before parsing body; when newer request superseded it, data was dropped but tag stayed, every later poll got 304, and panel never showed answer (flaky smoke: ~1 run in 3). Race-test anything with overlapping fetches by firing two refreshes at once.
- The Needs panel and drawer share `#scrim`: whoever closes second must not leave it up or hide it from other (`closeNeeds(true)` = drawer is taking over; `openNeeds` closes drawer first, then shows scrim). `Esc` order in keydown handler: hint (`p`), command palette, `?` sheet, menus, panel, drawer, chat. Chat is third right-hand panel: opening any of three closes others (UI-58).
- `<input value>` drops newlines: multi-line draft collapsed back to one-line input shows them stripped, so `submitNeeds` sends `DRAFTS[key]`, not field's value.
- **"Waiting on <first word>" bug**: question's `waiting_on` is free text (question), never person. Cards and drawer show `Question from <asked_by>` for agent question and `Parked: <waiting_on>` for hand-set one; never split `waiting_on`.

## Speed rules

Each found by hand on slow Docker board (CORE-58); mechanics in "The cache" above and code comments.
- Read board ONCE per request or locked step; build reply from that read (CORE-61: `_claim` read every ticket 3 times).
- Know what changed from stamp (name + `mtime_ns` + size); re-parse only changed files (files cache; `knowledge` `_COMPS` CORE-59, `_EXP` / `_INFO` CORE-63).
- Own write drops cache at once (`FileBackend._wrote`, `_HAS.clear()`); time-based reuse only for what may lag (`SCAN_REUSE_S` 1 s, web only; `DEAD_TTL` 60 s), never under lock (`_held`: locked reads always stat) (CORE-60, CORE-59).
- One `os.scandir` walk using DirEntry type bits, not stat / `resolve()` per path (CORE-62, `knowledge.repo_files`).
- Request reads only board it is about: `GET /api/needs?board=` (API-18).
- Idle polls answer from cached body + ETag, rebuilt only when `Store.board_sig()` / stamps change; ticket JSON stable while idle (CORE-65; see Conventions).
- New GET route gets filesystem-call budget in tests/test_perf.py (counts, not wall clock; ~1.5x measured) (CORE-64).
- Measure slow case: ~500 tickets on Docker Desktop bind mount (~0.6 ms per stat, 75-100x native; docs/reference.md) (DOCS-16).
- Keep LF line endings: worktree `core.autocrlf false`, `git diff --stat` must equal `git diff --ignore-cr-at-eol --stat` (CRLF flip made 52-line PR #82 show 2,500 lines).
- Claim before you start, even in your own worktree; pass `--branch` / `UNBLOCKD_BRANCH` so touches overlapping claim on another branch warn, not refuse (CORE-80).

## Tickets: unblockd board `unblockd`
Work on this repo is tracked as tickets. Follow the worker protocol (MCP prompt `work_loop`, resource unblockd://work-loop); in short:
1. Claim before you start: `claim_next(agent=<profile>-<n>)` or `claim_ticket(id, agent)`. Never build on a ticket you did not claim.
2. Read the ticket, ALL its notes and its `context` first; `done_when` is the bar for done.
3. `heartbeat(id, agent, note)` at least every 5 minutes: a silent claim expires and the ticket goes back to todo.
4. Finish with `complete(id, agent, summary, files, refs)`: cause -> fix -> tests; NOT verified: ... Never move a ticket to done with update.
5. A decision only a human can make: `ask_human(id, agent, question)`. Can't finish: `release(id, agent, reason)`.
Without MCP: `python -m unblockd.cli --dir tickets claim --agent NAME [--id ID]`, `heartbeat ID --agent NAME --note ...`,
`complete ID --agent NAME --summary ... --file PATH --ref PR`, `ask ID --agent NAME --question ...` (other machine: set UNBLOCKD_URL).
